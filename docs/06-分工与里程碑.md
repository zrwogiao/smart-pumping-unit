# 06 分工与里程碑

本项目模块边界清晰，适合 4 人小组并行开发。若人数不同可按角色合并。

## 角色分工

| 成员 | 主责 | 涉及文件 |
|---|---|---|
| A（后端） | 数据模型、API、WebSocket、定时任务、告警控制 | `backend/app/models`、`api`、`tasks`、`ws`、`services/*_service.py` |
| B（算法） | 示功图模拟、特征提取、三层诊断 | `backend/app/services/simulator.py`、`features.py`、`diagnosis_service.py`、`constants.py` |
| C（前端） | 全部页面与 ECharts 组件 | `frontend/src/views`、`components`、`composables` |
| D（文档测试） | 文档、测试用例、答辩演示脚本 | `docs/`、`backend/tests/` |

## 里程碑

| 里程碑 | 内容 | 产出 |
|---|---|---|
| M0 骨架 | 目录结构、依赖、配置、数据库初始化、前后端联通 | 可运行的空壳工程 |
| M1 数据与模拟 | ORM 模型 + 种子数据；simulator + features | 可生成 6 类示功图 |
| M2 诊断与 API | 三层诊断；四大模块全部 API + WebSocket + 定时任务 | `/docs` 可调试全部接口，数据持续写入推送 |
| M3 前端页面 | 核心组件 + 9 个页面 | 所有页面可访问，大屏可演示 |
| M4 联调闭环 | 前后端字段对齐；模拟→诊断→告警→确认/清除闭环；报表导出 | 端到端完整系统 |
| M5 文档答辩 | 7 份文档、测试用例、演示脚本、分工演练 | 完整交付物 |

## 协作约定

- 算法层 B 提供纯函数接口（`diagnose(disp, load)`、`generate_dynamo(condition)`），后端 A 直接调用，解耦清晰。
- 前后端以 OpenAPI（`/docs`）为接口契约，字段命名保持一致（snake_case）。
- 每人负责的模块独立提交，避免交叉修改同一文件。
